## Decisions by subsystem

| Task | Our current implementation | Best useful comparison and decision |
| --- | --- | --- |
| Virtual device creation / `0x803b0006` | One globally reserved Add, bounded fresh event correlation, generation/provenance checks and ambiguity latch | Direct HID receipt is the strongest new candidate for removing klog attribution. Prepare it as a separate backend experiment using the same registry; do not mix raw HID handles with libScePad injection or automatically fall back after uncertain creation. |
| User assignment / native DualSense | Console picker, consensus user-list observer; local bind only on Steam/PS with one foreground user and confirmed disconnected native state | Keep this policy. Do not import remembered account IDs, fixed `user=1`, native disconnect/unbind, native-handle fallback or Shell patching from another project. The direct-HID descriptor's field names alone do not establish its user-assignment contract. |
| Logout/login recovery | Existing consensus, owned deletion and retry state preserve the USB connection | LibrePad's recovery idea is already incorporated with stronger transient/error/pause protections. Retain our tests and failed-deletion barrier. No hardware logout result was added. |
| USB endpoint selection | Full configuration validation, exact Valve IDs, live reopened-fd identity check, mapped Steam interfaces and validated input | Retain. padbridge's descriptor-driven selection is useful corroboration. AnyController's first-readable-endpoint search and interface-0 detach are unsuitable for a composite Puck. Do not cache rejection solely by device path across possible replacement. |
| USB IN/OUT and buffer lifetime | Multiplexed completions, completed-IN retention, retired cancellation indices and session-owned buffers | Retain. LibrePad's `usb_fs_collect`/`usb_output` supports the same ordering principle; our ownership and injected-failure coverage is already more explicit. No transport rewrite or foreign protocol handshake. |
| Short USB failures / reconnect | Neutralize, close owned session, create a fresh generation | LibrePad DS3 transport-only reopen is a useful future improvement. AnyController's three-second grace matches by driver type, which cannot establish physical identity. Preserve neutralization; retain a VDA across reconnection only with a justified identity contract and unresolved-transfer/deletion barriers. |
| Rest/wake | No dedicated system-power observer; watchdog/disconnect cleanup is the existing fallback | padbridge/xpad demonstrate the better design: quiesce owned input/USB, wait for working state, rediscover after wake. ## Direct `/dev/hid`: worthwhile, with an explicit contract

[FGG `src/vpad.c:13–71, 87–143`](https://github.com/FGGstore/FGG-XSense/blob/bfc5f9d324e2ca8b0a90fc498957699caa9fe5b0/src/vpad.c#L13-L143) and [AnyController `include/vpad.h:20–77`](https://github.com/BallerIsLeet/AnyController/blob/2eec5ec209f7e20369144de37e2358d1b2af0241/include/vpad.h#L20-L77) use Add `0xC018482A`, Insert `0x8018482C`, Delete `0x80104850`; Add receives a 24-byte request with a 168-byte descriptor and an explicit handle output. Delete uses a different 16-byte request. The input buffer is **160 bytes of kernel report format**, not `ScePadData`; buttons are at `+0x0c`, axes at `+0x10`, motion at `+0x78`.

The direct handle output is better attributable than a temporally nearby klog message. This is a source-derived engineering judgment, not proof of the complete kernel contract. Both examples forget ownership on failed Delete and do not establish our full touch/IMU/feedback contract. FGG says its PS-button experiment failed on FW11.60; AnyController says `0x10000` opens Control Center on FW13.60. Its FW4.00 issue demonstrates that visible registration alone does not establish accepted input. Do not generalize either PS-button result across firmware.

Next implementation must use the existing backend/slot authority, static ABI size/offset assertions and an injected ioctl seam. It must retain every ambiguous receipt and failed deletion, reject invalid/duplicate handles, keep descriptor/report buffers alive through synchronous completion, encode neutral/full Steam state correctly, and never use the returned raw handle with libScePad's separate write-handle table. Tests must cover Add success with invalid/aliased output, failure with changed output, Insert errors, failed Delete, cancellation, generation changes and no double creation. A controlled single-console test must then establish assignment, actual accepted input, PS action, touch/motion, native DualSense coexistence and owned cleanup on measured FW13.60. No active ioctl has been added in this audit; there is no inert configuration switch advertised as a working feature.

## SDK: inspect the actual change, keep v0.43

The [v0.43…v0.45 comparison](https://github.com/ps5-payload-dev/sdk/compare/v0.43...v0.45) contains seven commits: `killpg`, pkgconf compatibility, LLVM23, installation symlink handling, AGC stubs, Meson host-machine correction, and FW14.00/14.10 offsets. It changes neither USB headers nor `libc/syscalls.c`, Pad/UserService stubs or the existing FW13.60 branch. There is no demonstrated VDA/storage fix from upgrading, so the build pin stays v0.43.

`libc/syscalls.c:1841–1950` still emits the six raw *at() stubs without POSIX errno normalization. Keep our narrowly typed CF/RAX adapter and its descriptor-collision tests. Prefer already implemented libc/library functions where they provide the required contract; a named export stub proves symbol availability, not argument semantics. `crt/syscall.c` uses a libkernel entry before startup setup, while `crt/patch.c` adjusts the current process's syscall range and credentials before `main`. Thus our Safe Mode excludes application Shell/radio/hooks writes, but does **not** remove the SDK/loader's own firmware-dependent startup. Our credential guard restores its entry-to-main snapshot, not an unrecorded pre-loader state. Do not add a second startup patch or claim kernel-independent execution.

## Protocol conflicts and preserved data

SDL's [packed report structures:609–650](https://github.com/libsdl-org/SDL/blob/721cb0dd494503c3a7aad1ea6f3dae46cf4a6bfc/src/joystick/hidapi/steam/controller_structs.h#L609-L650) identify unsigned pressures at bytes22/28 including report ID; its [button fields:86–97](https://github.com/libsdl-org/SDL/blob/721cb0dd494503c3a7aad1ea6f3dae46cf4a6bfc/src/joystick/hidapi/SDL_hidapi_steam_triton.c#L86-L97) identify left-stick touch at byte5/bit0. These facts now extend the existing decoder without inventing PS5 outputs, changing bindings or normalizing unknown physical pressure ranges. Host tests cover both existing report IDs, independent surfaces, unsigned boundaries, touch release and no spurious buttons. Fixtures are source-derived/synthetic, not captured hardware.

Two discrepancies need identified controller/firmware captures before changing existing user profiles: SDL calls byte2/bit6 View and byte3/bit6 Menu, while pinned SteamlessController and our Puckbridge-derived mapping name them the opposite way. SDL scales gyro by `2000/32768`; our two motion paths use `1/16` (2.4% higher). This is a confirmed **source disagreement**, not proof that the user's device has swapped controls or wrong calibration. SDL also handles timestamped report `0x47`, which our decoder deliberately does not interpret as `0x42`. Do not feed an unimplemented layout into the current offsets. Follow-up fixtures must identify transport/report ID, physical button, sensor rate/orientation and firmware; keep account/device secrets out of captures.
