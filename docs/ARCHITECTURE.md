# Architecture contracts — specialization without monolith

## Current implementation checkpoint — dev.3

The diagrams describe logical contracts, including research boundaries. USB-C/Puck are implemented; a native BLE adapter is not. The current single-SC2 runtime keeps some process-wide state and inherited adapter logic; the contracts do not assert a completed transport-independent PS5 backend. Later sections supersede earlier audit descriptions where fixes changed behavior. In dev.3 there is no guessed-endpoint fallback or klog/GetHandle ownership promotion, cancelled USB indices remain retired until FS teardown, and the WebUI has four bounded clients. Only a positive receipt from the exact creation call can establish VDA ownership; its PS5 ABI meaning is still unverified.

## Target dependency direction

M1-242: the registry reserves Add globally until its result is recorded. A nonpositive/aliased receipt blocks future creation for that registry lifetime without guessing/deleting a handle; hotplug does not clear the latch. The USB worker rechecks identity from its reopened fd before mapping/detach, using a complete18-byte device descriptor when that read path is selected. See [runtime review](development/PUBLIC_RUNTIME_REVIEW.md). Published dev.3 predates these fixes.

## Contracts / API principles

`Transport`: own connection/hotplug; send/receive bounded immutable binary frames, timestamp and errors; no Steam protocol semantics. `DeviceIdentity` cannot be only USB path or transient BLE address. Persist pairing material securely and never log secrets.

`SteamProtocol`: parse versioned reports into typed `SteamRawState`, validate frame/report ID/length/endianness/signed motion fields. Emit `SteamOutputCommand`; pure decoding and host golden-vector tests. Supports USB/Puck/BLE without duplicating core parsing.

The first pure decoder, `payload/steam_protocol.c`, now returns typed SC input, battery, and wireless-link reports. Truncated known input reports retain their input classification so the adapter can publish a neutral state instead of leaving stale buttons/touch held. `payload/steam_usb.c` validates complete USB configuration descriptors for Puck and wired endpoint discovery, including fixed standard lengths (configuration/interface: 9 bytes; endpoint: 7 bytes), consistency between the configuration's interface count and distinct default-altsetting interfaces, and between each interface/alternate setting's declared and parsed endpoint counts. Duplicate default interfaces and maps larger than the fixed capacity fail closed instead of being silently accepted or truncated. `sc2_ep_map()` reads the configuration once and distinguishes an unavailable ioctl, a malformed descriptor, and a disconnected device; the same parsed map supplies candidate IN endpoints and the paired OUT map. Current Safe Mode rejects an unavailable configuration map before endpoint probing or driver detach; no guessed-endpoint compatibility scan is allowed. A malformed map or a valid map with no eligible HID IN endpoint fails closed. Active endpoint selection still requires a complete decoded input report. The pinned SteamlessController source defines vendor usage page `0xFF00`, controller usage `0x0001`, and Puck dock usage `0x0002` (`docs/SOURCES_AND_EVIDENCE.md`, S03); this is source-only evidence, not a captured Steam descriptor. The SDK declares `USB_GET_REPORT_DESC` and its generic descriptor fields (S10), but the target ioctl behavior and actual HID usage page remain unverified until an identified Steam Controller/Puck descriptor can be captured on hardware.

`usb_resources.c` owns the USB reader's descriptor, FS-init state, opened endpoint indexes, and possibly active transfers. `usb_session.c` routes reader open/init/endpoint-open/start/complete calls through a small injected operation table. The SDK's `USB_FS_COMPLETE` is `_IOR` and returns the completed endpoint index; the session callback exposes that index, clears the matching transfer bit, and reports when a different active endpoint completed first so the caller can keep polling. `usb_session_complete_any_transfer()` accounts for whichever active endpoint a multiplexed COMPLETE returns; START rejects an already-active endpoint, preventing a retry from overwriting an unowned transfer. Teardown stops active transfers, closes endpoints in reverse order, uninitializes only a successfully initialized FS session, and closes the descriptor once. Failed START and COMPLETE operations remain eligible for STOP during cleanup. Xbox handshake reads, Xbox/Nintendo OUT messages, and SC2 haptics use the same tracked transfer helpers; a failed STOP retains ownership for the common cleanup path. The SC2 candidate scanner receives the same `usb_session_ops_t` and context as the manager and routes candidate OPEN/START/COMPLETE/STOP/CLOSE through the shared session lifecycle. Since COMPLETE is multiplexed across the FS session, scanning refuses to begin while another transfer is active; each returned endpoint is accounted before its report is decoded. If STOP or CLOSE fails, the scanner preserves the outstanding ownership and returns the first error; `gc_main.c` skips ordinary scan reinitialization and sends the still-owned resources through session cleanup for another attempt. Host operation fakes cover concurrent report isolation, endpoint 1 completing before endpoint 0, preservation of a pre-existing active transfer, failed STOP/CLOSE retention and retry, and the expected cleanup. The fakes do not execute the production PS5 ioctl adapter, which is cross-build-only. No USB device path has been run on hardware.

`game_list.c` parses installed-title metadata for both the portal and the profile watcher. `param.json` is read into a bounded, per-call heap buffer and parsed by a pure helper; concurrent lookups never share mutable input storage. A deterministic host regression overlaps two real `gc_game_name()` calls after each file read and checks their names remain paired with their title IDs. It does not validate PS5 appmeta permissions or on-console file contents.

The retained 2015 wired-controller adapter also keeps its left-stick sample across reports because those bytes are reused for left-pad coordinates. That history is `steam_legacy_input_state_t` owned by the same `usb_session_state_t` that feeds the decoder; it is zeroed at reader start and is never shared between devices. The host regression checks both a newly started session and concurrent readers. This ownership fix does not imply that this legacy model has received physical PS5 validation.

The USB reader threads can report virtual-device insertion failures concurrently. `gc_diag_once_t` is a narrow synchronized claim used by `inject_pad()` to preserve one-time error logging without an unsynchronized static check-and-set; its host stress test runs 80,000 concurrent claim attempts. This protects diagnostic rate limiting only and does not validate PS5 VDA insertion results.

The optional game hooks stay in the game process's own mapped memory so a payload restart can reuse an identical layout. Each new layout records its gateway address; rollback restores a slot only when it still points at that gateway, treats an already-restored slot idempotently, and leaves a later owner's hook untouched. Read/write failures retain the old target ownership and retry; unknown/conflicting slot owners are not overwritten. The payload refreshes an audio-silence heartbeat with each hook-manager update, and game-side callbacks expire that mute lease after 120 stale output callbacks; merged input already ages out after 60 pad reads. A game process exit releases its own mapping. This is source/host-policy and SDK-build evidence only: no live game, cross-module hook race, explicit payload-stop behavior, or PS5 rollback has been exercised. In particular, a pointer check followed by a remote write is not an atomic compare-and-swap, so target concurrency still needs a safe console test.

Small platform-independent operations are factored into `steam_mapping.c` (axis/trigger, d-pad and trackpad transforms), `steam_motion.c` (unit conversion, bias handling and quaternion integration), and `steam_feedback.c` (bounded pulse/rumble report serialization). `webui_json.c` supplies bounded JSON string/number output to the authenticated portal. `slot_registry.c` is the one authoritative owner of live slot metadata: session key, VID/PID, lifecycle state, generation and virtual-handle ownership. The manager claims a session and rejects duplicate live keys atomically; its generation token travels into the USB reader, which snapshots, attaches, detaches and releases only that generation. Registered VDA handles are unique across slots. The backend deletion callback runs outside the registry lock; on failure the registry restores ownership, moves the slot to `RELEASING`, and the manager retries cleanup on later scans. `slot_lifecycle.c` owns the reusable startup/rollback/release transaction now called by `gc_main.c`: reserve tokens must be active before worker startup, failed worker creation removes only registry-owned VDA handles, and delete failure leaves the generation unavailable for a later retry. Host fault-injection covers VDA-create failure, worker-start failure, ambiguous handles, lazy/eager startup and delete retry; a four-thread stress test exercises 4,000 lifecycle cycles. The target scan loop, PS5 callbacks and USB I/O remain cross-build-only. Profile and `ScePadData` mapping state, USB I/O and VDA calls remain in the inherited PS5 adapter; this is not yet the canonical transport/session architecture. A `/dev/ugen*` path is only a live-session key, not a stable physical identity, and no USB↔Puck↔BLE rebind continuity is claimed. Do not infer PS5 behavior or hardware support from host/build tests.

Numeric profile fields use checked `strtol` parsing with full-input and `int`-range validation; malformed or overflowing values leave the prior/default field intact. Combo parsing uses a call-local tokenizer so the profile watcher and authenticated portal can parse concurrently without sharing `strtok` state. Binding activator state is caller-owned per slot; initialization, reset epochs, and active-profile generation changes clear pending state, seed physically held inputs, and ask the adapter to publish one fully neutral pad report. Pause state uses atomic load/exchange, while external menu-close callers set a request that the input thread applies to menu-owned state. Host ASan/UBSan tests cover numeric bounds, concurrent parsing, profile-generation changes, long press, asynchronous reset requests, session isolation, and atomic pause-state access; ThreadSanitizer passes the profile-parser, binding-reset, and pause-state concurrency targets. They do not validate full profile persistence/browser integration, menu/input-thread integration, or the PS5 adapter's `ScePadData` publication.

Profile selection snapshots the game/override inputs with a generation, performs profile discovery and file loading without holding the selection mutex, then revalidates the generation before publishing the active profile and selected ID together. New override, reload, game-title, or title-name updates invalidate older in-flight selections. A deterministic regression delays an old reload until after a newer portal-style override commits; without the generation check, the stale mapping becomes active again. This prevents the older operation from overwriting the newer choice without holding a UI or input lock across disk I/O. Selection remains process-wide under the enforced one-SC2-session policy; menu, portal and watcher runtime integration is host/build-only.

`sc2_store_save()` and `sc2_store_delete()` share a process-wide storage mutex, so menu, portal and title-watcher mutations cannot race over the fixed `<id>.ini.tmp` path or resurrect a file across a concurrent delete. A successful save atomically renames one complete profile file into place; close and rename failures return an error and remove the temporary file where possible. The on-console remap action reports save errors and only reloads/notifies success after the store returns success. Loads do not hold the mutation lock, so a concurrent read can see the prior or next complete file. Independently edited stale snapshots still use last-writer-wins semantics; this is not a merge or optimistic-version API. Host regressions use the production storage and menu modules for overlapping save/save and save/delete operations, plus successful/failed remap persistence. Browser and PS5 filesystem integration remain unverified.

`sc2_status.c` owns the cross-thread diagnostics snapshot shared by USB/input workers, the manager, and the portal. Input mask/connection, battery level/state and warning thresholds, haptic availability/method/endpoint, and haptic counters are read or updated under one mutex; readers receive a coherent value copy. This replaces the former shared `volatile` telemetry globals and keeps warning hysteresis in the same critical section as battery updates. Host stress validates 100,000 concurrent snapshots under ThreadSanitizer and ASan/UBSan. The snapshot represents the current active Steam Controller path; it does not establish simultaneous multi-controller telemetry semantics.

`sc2_input_state_t` is owned by one USB reader session and carries that session's binding activators, flick-stick accumulator/frame timing, adaptive-trigger zone and buzz-expiry history, QAM hold latch, and menu-action edge history. The previous flick-stick, trigger-effect and button-edge fields were function statics, so two SC reader threads could consume or overwrite one another's input history. `sc2_input_state_reset()` initializes and clears the complete context at reader start, malformed-input neutralization, disconnect, and exit. Regressions reproduced both cross-session flick and trigger-effect contamination, then validated independent interleaved state and concurrent reports under ASan/UBSan and ThreadSanitizer. Trigger effect commands and enable state remain process-wide configuration guarded by a mutex; each reader snapshots the configuration and mutates only its own runtime state. The haptic service passes each caller's extra-OUT count directly to that send and clamps it to the endpoint-array bound; its log counters are serialized. `sc2_haptics.c` now gives the shared pulse queue and rumble state an exclusive generation-tagged slot-token owner: the manager claims before SC2 worker startup and refuses a second active SC2 USB/Puck reader; service calls must present that token to drain; release invalidates the owner, clears pending effects and best-effort sends a zero-rumble report before USB cleanup. Producer APIs remain process-wide and rely on this explicit one-session policy. Multi-SC2 haptic routing is not supported or claimed. The profile selector, menu, gyro integration, and status snapshot also retain process-level semantics.

The DualSense hand-off settings/session/release flags also use their existing mutex on every access, including hot-path checks. The hand-off test reproducer previously reported ThreadSanitizer races for enable and release state; the corrected path passes 60,000 concurrent JSON/session snapshots. The bridge-probe force request now uses its state mutex, and adaptive-trigger enable state is read/written under the effect mutex. These source-level race fixes have not been exercised on a PS5.

`game_hooks.c` protects settings, active state, owner selection, pad input and JSON-visible status with its shared mutex. The worker takes one coherent settings snapshot per iteration; settings persistence is serialized separately so concurrent UI changes cannot leave an older snapshot on disk. Persisted numeric values use checked `strtol`, reject trailing input and overflow, and accept boolean fields only as 0/1; malformed fields retain safe defaults. Its 61,000-operation host worker test and four malformed-settings checks pass ThreadSanitizer with mocked process/bridge calls. `sc2_gyro.c` protects the IMU/calibration/motion/reset/status state with one mutex, and serializes its USB-service retry state separately; callers use synchronized moving-state accessors rather than a shared `volatile` flag. The gyro state stress passes 75,000 operations under ThreadSanitizer. These tests do not execute PS5 USB ioctls, game process memory access, filesystem behavior, or console behavior.

The assignment dialog gate remains a separate atomic lease token containing a slot and generation. Only the exact token that acquired the gate can release it, so a delayed USB reader cannot clear a newer dialog after its previous lease timed out. Portable tests cover that lease, the slot registry, the shared lifecycle transaction's create/start rollback, ambiguous-handle protection, failed-delete recovery, concurrent startup/release, and USB session operation failures. The registry supersedes the inherited volatile slot table. The actual PS5 scan loop and ioctl adapter are not host-executed; stable physical identity, cross-transport rebind, kernel reader interruption and target runtime behavior still need validation.

`SteamSession`: controlled state machine `DISCOVERED → INITIALIZING → READY → STANDBY → RECONNECTING → CLOSED` plus failure transitions; lizard suppression, heartbeat, mode, battery, capability flags, cleanup. A session lease binds transport and physical identity without owning the PS5 virtual slot directly.

`ControllerState`: monotonic time, independent raw and normalized axes/buttons, independent rear controls, per-trackpad contacts+click and calibration, gyro[3], accel[3] with units and reference frames, battery, charging, optional flags. Keep unknown/missing fields marked absent; avoid overwriting good state with malformed input.

`Mapping`: stateless evaluation + bounded per-profile transition state (hold/double/chords/layers/gyro/gesture). Pure deterministic processing given timestamps and previous state. State transitions must release prior mapped buttons upon profile change/disconnect.

`SlotManager`: exactly one authoritative owner of live-session-to-virtual-slot metadata; transactional claim, activate, handle attach/delete, and release; generation tokens reject delayed operations after slot reuse. `slot_registry.c` enforces duplicate session-key and virtual-handle rejection, requires an explicit releasing state, preserves handles after backend delete errors, and is covered by portable concurrency/failure tests. USB path keys are ephemeral, so identity continuity across disconnect or transport switch, multi-user behavior, and zero duplicates on physical hardware remain unverified. VDA creation is serialized through generation-tagged creation reservations; klog notifications do not establish handle ownership or user binding. The assignment-dialog lease is a separate concern.

`PS5Backend`: isolated `VirtualDualSense` default; firmware-specific ShellUI bridges/hooks behind opt-in capability checks. Never let generic input modules call `libScePad` or ptrace. Backend can expose `CAP_TOUCH`, `CAP_IMU`, `CAP_FEEDBACK` only if implemented and tested.

`Feedback`: typed intensity/time/effect events, routing by current slot generation, safe intensity bounds, haptic/rumble fallbacks, output coalescing and cancellation. No feedback loop calling transport under a slot lock. No physical resistance on Steam triggers; can translate signals to haptic events.

`WebControl`: nonblocking, authenticated mutations through application layer; documented schema with version, error codes, limits, profile data migrations. No raw input socket enabled in release. Avoid conflicting web ports if selected base already has them.

`webui_http.c` owns bounded request framing and response writes independently of the PS5 socket ABI. The sequential portal server measures a 5-second absolute deadline for each request and response with a monotonic clock and caps each socket wait at 2 seconds; incoming or outgoing partial progress does not restart the deadline. Response headers and body share one deadline, including icon responses. It returns distinct timeout and I/O outcomes for writes, and timeout, malformed, oversized, and I/O outcomes for reads. Duplicate `Host`, `Origin`, and `Content-Type` fields are rejected. When a request supplies `Origin`, the handler accepts it only when it matches the request's HTTP `Host`; requests without `Origin` remain available to non-browser clients and still pass the independent bearer-token gate for `/api/`. Profile mutations require a non-blank body declared as `text/plain;charset=UTF-8`. Deterministic host tests exercise slow request/response progress, late reads, origin matching, duplicate headers, and profile-body metadata. This is defense in depth around the bearer token; actual browser/socket integration and PS5 behavior still need target validation.

`webui_auth.c` creates a 256-bit bearer token from `/dev/urandom` on first use and stores it as a 64-character hex file under `/data/ghostpad`. The directory is owner-validated and forced to mode `0700`; new token files use `0600` plus `O_EXCL|O_NOFOLLOW`. Existing token files must be regular files owned by the current effective user, have no group/other permissions, and contain exactly the expected token format; insecure or malformed storage disables the portal instead of replacing it. `/` is a public static page, while every `/api/` route requires `Authorization: Bearer …`; the browser keeps the entered token in `sessionStorage`. The tests cover secure creation, reload, permissive mode, malformed content and symlink rejection. The token still travels over plaintext HTTP; actual Prospero filesystem/API behavior has not been validated.

`webui_peer_policy.c` limits accepted peers to loopback, RFC1918 IPv4, or IPv4 link-local addresses before request parsing. Public IPv4 and IPv6 peers are closed without logging their address. This preserves ordinary home-LAN access while reducing accidental internet exposure; it does not encrypt plain HTTP or replace the API bearer token. The pure range policy has host tests, while the Prospero `accept()` and address representation need console/network validation.

`webui_route.c` owns the portal's method/path/query contract. It matches complete route paths, applies a per-route query-key allowlist, rejects malformed or duplicate parameters, and copies values into caller-provided bounded buffers. The handler validates action-specific values before changing pause, haptic, DualSense, profile-selection, or game-hook state. Browser-generated profile IDs use the existing restricted ASCII alphabet, so the route parser intentionally rejects percent-encoded or other non-ASCII query values. Host route tests cover every registered path, prefix aliases, key spoofing, duplicate/unknown keys, malformed delimiters, output bounds, and GET/POST policy. They test the portable router, not socket-to-handler behavior; the live portal remains target-unverified.

`HAL`: dependency injection or light function-table wrappers only where a real test/platform seam exists (clock, USB, BLE transport, socket, storage, OS virtual pad). Avoid pointless generic factories or unused backend interfaces.

## Invariants to test

1. One physical controller -> at most one active virtual device generation; every disconnect frees all outputs.
2. Every packet validated before state update; no stale pressed input after transport timeout.
3. One normalized extended input format across transports with consistent coordinate and time units.
4. Output feedback never delivered to a disconnected/rebound controller.
5. No HTTP/TCP action bypasses authorization, ownership or domain validation.
6. If motion/haptics/hooks are absent, basic buttons/sticks work with safe fallback.
7. User profile/slot operations are atomic relative to incoming input and USB disconnect.
8. Shutdown is idempotent and preserves the native DualSense path.

## Extension requirement

A new controller in the future should require a new parser+capability adapter (and perhaps transport profile), **not** another slot manager, PS5 backend, web server, haptics router or pairing stack. A new transport should require a transport adapter, not a copy of the Steam report decoder or gyro engine. Prefer extending the best existing module rather than creating duplicate `*_v2` implementations.

## Image remapping portal (ADR-048)

Controller view geometry lives in `payload/web/controllers/layouts.json` and is embedded with four WebPs by the existing HTML generator. The web adapter maps reference shape IDs onto the existing `BITS` and `OUTS`; repeated front/back hotspots share one logical key. `buildPad` creates input/output/transaction-preview views, `paintPad` and `paintDestinations` derive highlights from current profile or active dialog draft, and `openSheet`/`closeSheet` retain the profile transaction boundary. The UI never mutates driver state directly. `render` refreshes assignments after load/import/undo, and the existing bearer-authenticated INI API handles persistence. Every asset participates in Make dependencies. No additional server, parser, remapping schema or PS5 ABI is introduced. Portable embedding contracts run in Host CI; a loopback browser fixture is distinct from console runtime evidence.

## Remap validation and canonical persistence (ADR-050)

The browser validates imported input/output identifiers, activator suffixes and known settings before an atomic merge. Rendering assignment rows uses DOM nodes; all binding badges accept only `OUTS` identifiers. INI parsing uses a null-prototype object. `normalizeBindingFlags()` and the C parser apply the same Toggle-over-Turbo conflict rule. Shift inputs emit no button output, including a trigger hardware full click; stored bindings and analog-axis behavior are retained. Save captures the profile ID and submitted snapshot, POSTs it, then GETs and validates the complete canonical profile. It replaces only an unchanged local draft; later edits remain dirty and a late result cannot replace a different profile. Failed/malformed readback is explicitly unconfirmed.

Coarse-pointer hit selection uses native SVG fill containment and transformed boundary segments, not rectangle overlap. Exact disjoint y extents cover shoulder pairs; browser tests sample every output fill and actual touch edges in both views. The host-only preview compiles a bounded stdin adapter to production `sc2_profile_parse`/`sc2_profile_format`; profile storage stays in RAM. This adds no payload API, transport/parser duplication, PS5 ABI or device state mutation.

### First-launch authentication and audited ownership (dev.2)

An absent policy enables only WebUI; malformed/unsafe existing configuration fails closed. `webui_auth` owns CSPRNG code lifetime, attempt budget, mutex redemption and existing permanent-token storage. `webui_http` performs Origin/Host and bearer admission before reading bodies. Four tracked clients prevent a single slow unpaired client from blocking enrollment; API dispatch remains serialized. Shutdown joins clients before erasing credentials.

USB endpoint frame storage belongs to the session, and busy endpoint metadata is immutable until completion/cancellation. Valid successful single-frame input refreshes the input watchdog; expiration uses the owned session cleanup/neutralization path. Idle Puck discovery holds no active Steam feedback lease. Physical USB ioctl/cancellation timing remains unverified.

Hook import changes are transactional. Partial writes retain rollback ownership; unused remote pages are unmapped or tracked for retry. Any retained old hook page causes read-only refusal until the game restarts, rather than unverified capability reuse. Pages reached by import slots remain until process exit because callbacks may still be in flight. Optional hooks remain disabled by default.


## Dev.3 session recovery and diagnostics (ADR-055)

`user_session` is a portable mutex-protected value observer. The manager supplies read-only SDK user-list/foreground results at2s intervals; three consistent empties after prior presence establish one logout epoch, two same normalized lists establish relogin. Invalid/error/rapid observations reset consensus and suppress new registration. Startup at the login picker remains valid. The observer stores IDs only for comparisons; exported snapshots contain counts/flags, no account IDs. No user binding API or native pad operation is added.

The existing USB worker owns `slot_recovery`: proven owned old VDA deletion, deferred registration, retries and state eligibility. Registry creation reservations prevent concurrent Add and retain a positive receipt across release races. Failed deletion retains the old handle and prevents duplicate creation. An alias inhibits every future Add for this registry; cleanup deletes only an independently owned handle. Recovery does not reset USB, mappings, gyro/touch decoder or haptic ownership. PS5 UI still selects accounts.

`usb_resources` separately owns active, completed-but-unconsumed and cancelled-retired endpoint masks. OUT can collect IN without discarding its data; only the IN consumer clears its completed bit. Cancelled indices cannot be restarted until FS teardown, so a late completion cannot be assigned to a new request. Existing session-owned frame buffers remain immutable while ownership is unresolved. A500ms valid-input watchdog neutralizes through existing owned cleanup; optional failed output does not require abandoning healthy input.

`diagnostics` copies bounded typed values under its own short mutex and formats outside the lock. It uses a48×192-byte filtered application memory ring; no filesystem reader, user-selected paths or raw kernel log export exists. The existing authenticated HTTP dispatcher produces a <=24KiB fixed-name text attachment; browser Blob URLs are revoked after download. Runtime firmware is measured, SDK/version fixed and source identity generated from selected SHA (dirty builds explicitly unknown). Configuration/profile/gyro/haptic data comes from existing services without UI driver mutation. The single-ELF tile remains opt-in and unchanged.
