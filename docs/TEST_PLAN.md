# Verification matrix and reproducible testing

Tests are evidence, not intentions. `project-memory/TEST_LOG.md` records executed commands, exits, and environments. The matrix below distinguishes complete host verification from partial tests, unrun target work, and research blockers.

Current portable targets are in `tests/Makefile`: `make -C tests test` and `make -C tests sanitize`. The latest suite passes 1048 counted assertions under ASan/UBSan: HTTP/auth/token and request-policy checks 99, peer-address policy 18, exact portal route/query handling 54, JSON writer 9, USB configuration parsing 19, Steam report decoding 190, mapping transforms 24, motion math 25, feedback serialization 20, profile parsing/concurrency 33, profile-selection generation 10, profile storage concurrency 22, on-console menu persistence 9, binding transitions/session isolation/reset epochs 49, atomic pause/assignment control 51, slot registry 123, slot lifecycle 85, USB resource tracking 66, USB session operation fault injection 70, game-hook safety policy 16, game-hook settings validation 4, per-session flick isolation 13, trigger-effect isolation 11 and haptic queue/session ownership 28. Seven stress targets pass 340,000 concurrent operations/snapshots, including hand-off (60,000), telemetry (100,000), game hooks (61,000), gyro (75,000), flick (20,000), trigger effects (20,000), and haptic service (4,000). The parser property target adds 100,000 deterministic randomized Steam report inputs and 100,000 USB configuration inputs under ASan/UBSan; this is bounded coverage, not exhaustive fuzzing. The SC2 endpoint-scanner regression runs two concurrent ioctl-stubbed scans and verifies independent report classification. The game-title regression overlaps two `gc_game_name()` JSON reads and checks title/name pairing. `gc_diag_once_t` is stress-tested with 80,000 concurrent claim attempts, and exactly one caller may claim the diagnostic. Targeted ThreadSanitizer passes concurrency targets, including profile-storage serialization, profile-selection generation, profile parsing, binding reset, pause/assignment control, slot registry, and slot lifecycle. Assignment lease tests cover 16,000 claims; registry tests cover 8,000 reserve/activate/release claims; lifecycle tests cover four concurrent workers with 4,000 startup/release cycles plus create failure, worker-start failure, ambiguous VDA handles, lazy startup, and failed-delete recovery. USB session fakes inject open, FS-init, endpoint-open, transfer-start, and transfer-completion failures and verify cleanup ownership; these test the portable adapter contract, not the real PS5 ioctl implementation. Game-hook safety tests exercise restore decisions and heartbeat-lease expiry, not remote memory operations. Stable device identity, rebind across transports, full profile persistence/browser integration, menu/input-thread integration, the PS5 adapter's neutral-publication branch, live USB/Puck I/O, and physical console behavior remain unverified. See `project-memory/TEST_LOG.md` for exact commands and environments.

Gate labels describe the cases actually executed, not the intended target coverage. `PARTIAL_HOST_VERIFIED` means the pure module has host checks but at least one listed integration or edge case is still open.

### Host build / CI

- Use existing native build/test targets after inspection; repair missing Makefile referenced tests first where applicable.
- Enable strict C warnings and ASan/UBSan in an isolated host-test build. Use fuzz/property testing for parsers and HTTP/profile inputs when useful and reproducible.
- A sanitizer build passing does **not** validate PS5-only memory/hook behavior. No crossbuild fake shims substituted for runtime result.
- Store compiler flags, SDK commit, OS/arch, command line, test count, exit code and log or GitHub Actions URL.

## Security/ABI/build gates

- PS5 cross ELF build: use the pinned SDK v0.43 asset and verify its SHA-256, build the payload, record the ELF SHA-256, and inspect target dependencies/imports. M1-41 passes those compile/link checks for the USB session integration. This is build-only evidence and does not verify firmware/runtime or USB/Puck behavior; keep those hardware gates separate.
- Native radio: **no active HCI experiment** without approval and safe plan. Strong evidence required for LE scan, not Bluetooth UI visibility.
- Game hooks: per-game/process build fingerprint, slot-owner checked rollback, liveness lease expiry, and basic input unaffected when hook disabled/fails. Current removal checks are not remote atomic compare-and-swap; require hardware validation before claiming race-free rollback.
- Licenses: scanned code and assets, required notices, no BTstack copying without review, no official NDA SDK redistribution.
- PR: `git diff --check`, host tests, sanitizer report, SDK build result/hardware status, scope/attribution and rollback in description.
